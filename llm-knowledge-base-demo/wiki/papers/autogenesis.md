# Autogenesis

Autogenesis is useful for this wiki because it turns agent improvement into an auditable loop.

## Why It Matters

Static agents age as tools, environments, and requirements change. Autogenesis separates stable resource access from a self-evolution layer that can generate, reflect, improve, evaluate, and commit changes. The important part is not only self-modification. It is self-modification with lineage, access control, tests, and rollback.

## Key Ideas

- Resource Substrate Protocol Layer for tools, prompts, environments, and memory
- Self-Evolution Protocol Layer for validated change loops
- Version lineage and reversible lifecycle operations
- Multi-agent evolution across planner, executor, and analyst roles

## Connection To This Demo

The demo can borrow the same pattern at markdown scale. A compiler pass proposes wiki changes, a lint pass checks links and thin pages, and accepted changes become durable files that future agents can inspect.
